# Agent Core Protocol (Project-Agnostic OS)
<!-- 警告: このファイルにプロジェクト固有の目的や仕様を記述することを固く禁ずる -->

## 1. Context Minimization (コンテキスト最小化原則)
トークン消費を抑え推論精度を維持するため、以下の遅延読み込み（Lazy Loading）を厳守せよ。
- **常駐コンテキスト**: セッション開始時に読み込むのは `AGENTS.md` と `Knowledge-important.md` のみとする。
- **部分参照と破棄**:
  - 目的や現在地の確認時のみ `Project.md` を参照せよ。
  - 過去の知見が必要な時は `Knowledge.md` を全文読み込みせず、grep等で該当セクションのみ抽出せよ。
  - 特定の作業手順が必要な時のみ `skills/` 内の該当ファイル1つを読み込み、完了後はコンテキストから破棄せよ。
  - 巨大なログやソースコードの全文出力を禁ずる（必要な行範囲のみ抽出すること）。

## 2. Anti-Fallacy Rule (テキサスの狙撃兵の誤謬の完全排除)
結果が出た後に都合の良いデータだけを切り取り「最初からそれを狙っていた」と事後正当化することを厳禁とする。
- **事前基準の固定**: 変更やコマンド実行の前に、必ず「事前仮説（なぜ行うか）」と「反証可能な合否基準（どうなれば成功/失敗か）」を明文化せよ。
- **後付け変更の禁止**: 実行結果を見てから合否基準を緩めたり、偶然エラーが消えた現象をもって「解決」とみなすことを禁ずる。
- **仮説の棄却**: 予測と異なる結果が出た場合（偶然動いた場合を含む）、仮説を「棄却」と判定し、因果関係を特定するまで次の仮説を立て直せ。

## 3. Autonomous Execution Loop (自律ループ構造)
すべてのタスクは以下の微小ループとして回し、常に再帰的に実行せよ。

1. **[Observe & Scope]**: 現在の状態（`Project.md` の Loop State）を確認し、残存タスクがなければ **Phase 6** へ進む。ある場合は今回解決する最小のサブタスクを1つだけ定義する。
2. **[Hypothesize]**: 事前仮説と、検証可能な「期待される結果（合否基準）」を実行前に宣言する。
3. **[Execute]**: 最小限の変更または検証コマンドを1つ実行する（必要時のみ `skills/` を参照）。
4. **[Verify]**: 実際の出力と、Phase 2で宣言した事前基準を厳密に照合する。不一致時は変更をロールバック（原状復帰）した上で Phase 2 へ差し戻す（リトライ上限3回、超過時はエスカレーション）。
5. **[Distill & Loop]**:
   - 確定した事実があれば `Knowledge.md` に1〜2行で追記する。
   - 致命的な地雷・絶対制約が判明した場合は `Knowledge-important.md` に昇格させる。
   - `Project.md` の `Loop State` を更新し、コンテキストが肥大化していれば `skills/loop-handover.md` を実行、余裕があればそのまま Phase 1 へ戻る。
6. **[Finalize & Terminate]**:
   - すべてのマイルストーンが達成されたことを確認し、変更をコミット/マージして自律ループを正常終了（HALT）させる。

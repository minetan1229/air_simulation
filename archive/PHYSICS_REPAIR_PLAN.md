## 1. 最終目標と方針

最優先は、手元からの上昇、頂点付近での機首下げ、安定滑空、着地を一続きの6DoF計算で実現すること。
優先順位は「物理基盤と上昇・遷移の修正 → 滞空プリセットのフルフライト化 → UI・カメラの整合 → 全体検証」。

基準ケースは高度1.8 m、初速26 m/s、投射角78°。設計探索範囲は高度1.8〜2.0 m、速度25〜28 m/s、投射角75〜80°。
最高高度15〜17 m、滑空25〜30秒以上、合計30秒超は対象機体について検証する性能目標であり、全プリセットに保証する値ではない。
到達高度・上昇時間・滞空時間は空力、質量、形状、初期姿勢で変わる。目標達成前に達成済みと表示しない。
不足する場合は実測根拠、モデル限界、設計変更の必要性を報告する。目標値へ合わせるための姿勢固定、頂点での状態置換、速度追加、架空の熱上昇流を使わない。
既存仕様の「姿勢安定化」は、相対気流に基づく空力・空力弾性で実現する。自由飛行に人工的な振り子トルクは加えない。

## 3. P1: 最優先 — 物理基盤と上昇〜頂点〜滑空

### P1-0: 基準ログと共通契約の確定
担当: Manager
対象: physics/config_schema.py、physics/geometry_utils.py、tests/test_physics_audit.py、検証用スクリプト

- 現状の基準ケースを着地または60秒まで実行し、失速・ループ・発散・未着地もそのまま記録する。
- 投射角、機体ピッチ、release_pitch_deg、迎角の関係を整理し、初速方向と姿勢の混同を解消する。
- ログに時刻、位置、相対対気速度、迎角、横滑り角、ピッチ角速度、動圧、力、モーメント内訳、エネルギー、応力を残す。
- 形状からの慣性、相対風からの力変換、単一の大気状態、空力弾性状態の共通契約を先に確定する。
- 修正前後のログを同条件で比較できるよう、設定・モデル版・時間刻み・乱数seedを保存する。

完了条件: 失敗状態を隠さず再現でき、各量の単位・座標系が明示されている。

### P1-1: 慣性・座標系・大気状態を修正
対象: config_schema.py、geometry_utils.py、flight_sim.py、aero_domain.py、mesh_domain.py

- 監査1: 形状と質量分布から慣性を算出する。任意形状で I_x ≤ I_y + I_z 等の三角不等式、対称性、正定値性を検証する。
- 監査7: メッシュ由来の慣性テンソルを機体座標で保持する。主軸を使う場合は形状・力・角速度も同じ座標へ変換し、固有値の大小だけで軸を割り当てない。
- 監査8: 空力係数評価に使う補正迎角と、力の座標変換に使う実際の気流方向を分ける。横滑りを含む3D変換を実装する。
- 監査6: 各RK4評価点で算出した大気状態を空力計算へ渡し、揚抗力、Re、Mach、応力で同一の密度を使用する。

完了条件: 平板・直方体の解析慣性、回転座標での等価性、揚力と相対風の直交、抗力の非正の仕事、高度による動圧変化を独立に検証する。

### P1-2: 人工復元トルクを除去し、失速・低速モデルを整備
対象: flight_sim.py、aero_domain.py、tests/test_aero.py、tests/test_flight.py

- 監査2: 世界座標の水平姿勢／トリム角へ戻す振り子トルクを除去する。ロール復元も横滑り等の空力条件に基づかせる。
- 監査3: 付着流の抗力極線と剥離流の圧力抗力を連続的に接続する。90°・負迎角・逆流で妥当な力の方向と大きさを確認する。
- 失速フラグ・失速余裕を正負の迎角とモデルの遷移域に整合させる。
- ピッチ減衰は q S c C_mq × (角速度 c / 2V) の単位と係数定義を統一する。既存の倍率・重複項を確認する。
- V→0で流れ角が不定になる処理を整理し、空力が滑らかに消えるようにする。速度ゼロで自動的に頭下げするトルクは設けない。
- 付加質量を有効にした場合の相対流加速度・回転連成・重力の扱いを点検し、対応していない項を明示する。
- 地面ピッチ補正が aero_domain と flight_sim の双方にあるため、二重計上を除去する。

完了条件: 空力ゼロ・重心まわり外力モーメントゼロの自由飛行で人工的な姿勢復元が発生しない。剥離流、低速、負迎角で発散しない。

### P1-3: 後縁しなりと自然なプッシュオーバー
対象: config_schema.py、aero_domain.py、stress_domain.py、flight_sim.py

- 現行 aeroelastic_compliance の単純な cL0 / cm0 減衰を評価し、有効後縁角と揚力・モーメントの連動モデルへ整理する。
- 動圧、剛性、紙厚、後縁形状による変形を定義し、必要なら有限の応答時間を導入する。応答時間がある場合は変形を積分状態として扱う。
- 高動圧で頭上げを抑える符号を検証し、低動圧で基準トリムへ連続的に復帰させる。頭下げ方向は形状・折り方に依存するため全機体に固定しない。
- 頂点の機首下げは静安定、空力中心・重心、角速度減衰、残る相対風により生じる設計とする。
- 紙剛性ゼロ近傍の暴走を防ぐ制約は物理的適用範囲として明示する。
- RK4途中の係数評価で共有設定を変更しない。変形・トルクはリプレイ／保存／復元でも再現する。

完了条件: 硬い機体との比較でループ抑制を説明でき、高動圧から低動圧への連続性と設定変更への応答を確認する。

### P1-4: 構造荷重と応力の修正
対象: stress_domain.py、flight_sim.py、tests/test_stress.py

- 監査4: 翼根モーメントを左右翼の荷重分布の積分から算出する。n=L/Wを動圧に重ねて掛けない。
- 空力荷重と翼自体の慣性荷重を分け、基準荷重の由来をログに残す。
- 監査5: 断面係数による σ=M/Z を基準にSI単位を整合させ、メッシュ解像度への依存を除去する。
- 紙厚、折りによる断面、材料許容値の根拠と経験係数の単位を明記する。
- 応力に基づくしなりを使う前に荷重モデルを確定する。根拠不足の破断判定は校正済みと表示しない。

完了条件: 同じ空力係数で速度倍増時の空力荷重が4倍になる。片持ち梁の解析解との一致、メッシュ細分化による収束を確認する。

### P1-5: 全飛行の性能検証
対象: tests/test_flight.py、tests/test_physics_audit.py、検証ログ

- 基準ケースから頂点を越え、下降滑空・着地まで初期化なしで追跡する。
- 初回頂点を上昇から下降への垂直速度符号変化として求め、上昇時間、頂点高度、遷移時間、滑空時間、合計時間を分けて記録する。
- 滑空開始は速度、迎角、ピッチ角速度、沈下率が定義した許容域に一定時間入った時点とし、評価閾値を設定と共に保存する。
- 最初は無風・乱流なし・熱上昇なしで検証する。続いて速度25/26/28 m/s、角度75/78/80°、高さ1.8/2.0 m、剛性・重心・トリムの感度を調べる。
- ループ回数、失速時間、地面到達、数値発散を測る。瞬間的な失速を一律禁止せず、回復と持続滑空を判定する。
- dt、dt/2、dt/4で最高高度と飛行時間が収束することを確認する。暫定許容差1%とし、収束結果に基づき固定する。
- 最高高度15〜17 m、滑空25〜30秒以上、合計30秒超の実現可否を報告し、未達なら校正の根拠とモデルの不足を記録する。

完了条件: 基礎物理検証を通過し、基準ケースの連続した上昇・遷移・滑空を実証する。性能未達の場合は未完了として扱い、表示だけを達成扱いにしない。

## 4. P2: データ層 — プリセットとAPIのフルフライト化

対象: records_domain.py、config_schema.py、app.py、tests/test_records.py、storage_domain.py

- フライト開始モードを flight_mode=full_flight|apex_glide として明示する。
- calibrated は出典／校正の選択属性として分離し、フライト開始モードの代用をやめる。
- 滞空プリセットの新規選択は full_flight を既定値とし、各機体の手元投擲条件を使用する。
- 現行の頂点開始レシピは apex_glide として保存する。校正値の変更履歴と元の設定を残す。
- 旧APIで flight_mode 未指定のリクエストや保存データは、旧挙動を再現する互換経路を設ける。新UIは必ず flight_mode を送る。
- /api/v1/records/apply と専用記録スタジオの評価経路を揃え、モードと実際の初期状態を応答に含める。
- evaluate_flight は発射からの実積分時間を合計時間とする。頂点開始の結果へ仮想の上昇時間を加算しない。
- JSON/CSVにモード、初期条件、上昇・遷移・滑空・合計時間、校正根拠、モデル版を含める。
- APIの不正モードは400とし、設定保存／読込／再実行でも同じ条件を維持する。

完了条件: 各滞空機の両モードでAPI、評価、保存・復元が一致する。頂点開始の校正滞空時間をフルフライトの実証値として表示しない。

- 初期カメラ、追尾範囲、near/far、軌跡境界を調整する。実際の最高高度に追従し、固定17 mの前提にしない。

## 6. 実装体制と依存関係

既存AGENTS.md §8.6に沿い、契約確定後に担当ファイルを排他分担する。利用可能な同時実行枠に合わせ最大3 worker＋Managerで順次組む。

1. Phase 0: Managerが基準ログ、config_schema / geometry_utilsの契約と検証基準を確定。
2. Phase 1A: aero-physics、atmosphere-fluid、structural-stressを並列化。依存する空力弾性の統合は荷重契約の確定後。
3. Phase 1B: flight-dynamics、mesh-3d、job-eta-storageを分担。records_domainはManagerが担当。
4. Phase 2: ManagerがAPI、プリセット、UI、統合テストを結合。P1完了をP2の校正確定の前提とする。
5. Phase 3: 各workerへ担当pytest強化と解析解・GPU/NumPyフォールバック確認を依頼。

各workerに「担当ファイル限定変更」「config_schema準拠」「Zero-Placeholder」「実pytest出力の報告」「GPUフォールバック確認」を明記する。
UIファイルはManagerの所有とし、別workerへ委譲する際はその期間Managerが編集しない。
並列化は契約依存を無視して行わない。物理モデルの校正は基礎式と積分の修正後に行う。

## 7. 検証と完了判定

各モジュール修正後に対象pytestを実行し、通過後に次工程へ進む。旧式をそのまま写した期待値は、解析解や独立の不変条件へ置き換える。

最終チェック:
- python -m compileall physics app.py
- python -m pytest tests -q
- python smoke_test.py
- フルフライト／頂点滑空のAPI連鎖、全滞空プリセット、CSV/JSON往復、モードの旧データ互換
- Three.jsでの軌跡、カメラ、時間制御の実ブラウザー確認
- GPUがある環境のGPU実行と、GPUなしのCPU/NumPy実行。GPU未実行は「未検証」と記載

数値精度の基準:
- 解析解のある慣性、動圧、座標変換、ISA、Sutherland、梁応力: 適用範囲を明示し相対誤差1e-6〜1e-3。
- 空力係数・紙の空力弾性・材料破断等の経験モデル: 数値一致と実機妥当性を分け、測定値や文献による校正範囲を明記。
- 軌道: 時間刻み収束、無風時の揚力の非仕事性、抗力の散逸、外部入力なしのエネルギー収支を確認。
- 付加質量・変形がある場合は流体／弾性エネルギーの扱いを含める。比較対象が剛体エネルギーだけの場合、その限界を明記。

成果物は、修正コード、独立した回帰テスト、基準ケースと感度解析のログ、実検証結果、未検証項目一覧。
検証済みの実装のみ、既存のユーザー変更を混ぜず feat / fix / refactor 規約で段階コミットする。
完了予定時刻は基準実行の計測後に見積もり、未測定の所要時間や成功を約束しない。
